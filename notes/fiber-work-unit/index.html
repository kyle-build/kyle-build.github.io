Fiber 为什么要把工作切成小单元

React 16 之后的调和不再一次递归完整棵树，而是把工作拆成 Fiber 单元，每个节点都可以检查时间、暂停、复用。

这样做的直接原因是主线程不能被长时间占满：

  • 一次同步遍历整棵组件树，很容易超过约 50ms，变成 Long Task
  • Long Task 期间点击、输入、滚动都不会被处理
  • Fiber 把「算下一层 UI」变成可中断的循环：做一点、看一眼还剩多少时间、再决定继续还是让出去

和调度笔记合在一起看：

  • Fiber 解决的是 工作怎么切
  • Scheduler 解决的是 切完之后什么时候继续跑

源码实验仍在 react-core-learning 的 mini-react。本页只留结论。
